# Legal Review

Run the suite's specialist skills in sequence so each step feeds the next. This skill sets the order and the shared rules. The specialists do the work.

## The suite

| Skill | Job |
|---|---|
| **case-briefing** | What a supplied opinion actually holds. |
| **legal-logic** | Audit the reasoning in someone else's document. |
| **where-the-argument-breaks** | Find the weak point in the user's own draft and repair it. |
| **legal-persuasion-tactics** | Choose and draft the persuasive move. |
| **authority-checklist** | List every authority and what the document claims it stands for, for hand-checking. |
| **source-verification** | Check citations, quotations, facts, and figures against the sources. |

## Shared rules for every step

1. **Establish the frame once.** Before the first step, identify the forum, the decision requested, the procedural posture, the burden and standard of review, and which materials are actually available. Pass that frame to each later step.
2. **Use one set of labels for anything that depends on a source.** **Verified:** traced to a source that was inspected, with its location. **Contradicted:** the source says otherwise or lacks the content. **Unverified:** the source has not been inspected; say what would settle it. Never promote Unverified to Verified because something seems familiar.
3. **Never invent.** No authority, quotation, pincite, exhibit, fact, or concession that is not in the supplied materials or a source actually checked.
4. **Verification runs last.** Run authority-checklist and source-verification on the near-final text, and again after any substantive change.
5. **Say the plan in one line, then work.** Tell the user which steps you will run and in what order. Skip a step that the request or the materials make pointless, and say why.

## Sequences

**Responding to an opponent's filing**
1. case-briefing on the opinions the opponent's argument depends on most.
2. legal-logic on the opponent's document. Identify what to attack and what to concede.
3. legal-persuasion-tactics to choose the response's lead moves.
4. If the user drafts a response: where-the-argument-breaks on that draft.
5. authority-checklist, then source-verification, on the final response.

**Reviewing the user's own draft before filing**
1. where-the-argument-breaks on the draft.
2. legal-persuasion-tactics for the weak points that need a different move, not just a fix.
3. authority-checklist, then source-verification.

**Preparing for oral argument**
1. legal-logic on the opponent's brief, focused on the questions the court is likely to ask.
2. where-the-argument-breaks on the user's brief, read as the bench will read it.
3. case-briefing on the two or three cases most likely to come up.
4. legal-persuasion-tactics for answers, using answer-first delivery.

**Final check before filing**
1. authority-checklist on the final document.
2. source-verification against whatever sources are available. Report what remains Unverified and what source would close each gap.

## Output

Lead with what most affects the outcome, wherever in the sequence it surfaced. Then give each step's findings under its own heading, in the order run. End with:

- the single edit or action to take first,
- every item still Unverified, with what would settle it.

## If a specialist skill is unavailable

Do that step at reduced depth using the shared rules, and say that the full skill was not available.
